# 1. 产品概述
FlowDay 面向需要管理课程、科研、开发与个人事务的用户，将日程、Todo、可视化 Workflow、提醒和 AI 操作统一在一个私有工作空间内。

## 1.1 产品定位
产品以个人执行闭环为核心：用户在 Project 中组织内容，在 Workflow 中表达复杂流程，在 Todo 中定义可执行任务，在 Calendar 中安排真实时间，并由提醒系统保障到点触达。
Today 页面承担信息总览；深度编辑分别进入 Calendar、Todo、Project 与 Workflow。AI 主要负责自然语言解析、候选排程和批量修改预览，所有 AI 写操作都需用户确认。

## 1.2 核心价值
- 把“项目计划”与“今天要做什么”连接起来，减少流程图、任务清单和日历分散维护。
- 允许日程重叠，适配下载、等待、后台运行、会议与专注任务同时存在的真实场景。
- 通过可视化 Workflow 表达分叉、汇合、回环、延迟和里程碑，支持复杂科研与开发流程。
- 通过飞书群机器人、PWA/浏览器通知和站内通知形成多层提醒。
- 通过结构化 AI 操作降低录入成本，同时保留清晰预览、歧义候选和人工确认。

## 1.3 产品成功定义
| 维度 | 目标 |
| --- | --- |
| 计划落地 | 用户能从 Workflow 或 Todo 在少量操作内生成一个或多个日历时间块。 |
| 提醒可靠 | 网页关闭后，服务端仍能按计划触发提醒；失败时提供替代通道与可追溯记录。 |
| 自动化可控 | AI 不直接写入业务数据；所有创建、修改、调课和重排均展示预览。 |
| 复杂流程可读 | 具有分叉、汇合和循环的流程仍可通过画布、分组、折叠和自动布局保持可读。 |
| 多端可用 | 桌面端支持完整规划；移动端支持查看、状态变更与轻量编辑；PWA 可安装。 |

# 2. 产品目标与边界

## 2.1 V1 产品目标
- 建立统一的 Project/文件夹模型，支持无限层级嵌套与私有数据隔离。
- 提供完整日历视图、重叠显示、拖拽排程、重复日程和 Apple Calendar 双向同步。
- 提供普通 Todo、子任务、重复 Todo、优先级、难度、预计/实际耗时和多时间块。
- 提供单 Project 单 Workflow 画布，支持自由连线、条件、AND/OR、回环、分组和里程碑。
- 提供自然语言 Inbox、结构化 JSON、AI 候选排程、AI 调课和变更预览。
- 提供飞书提醒、强提醒、PWA/浏览器兜底、站内通知和网页内日报/周报。
- 支持课程文件导入、课程 Project 组织、全局课程提醒和单课覆盖。
- 提供回收站、归档、自动备份、JSON 导出、数据库快照与按日期恢复。

## 2.2 V1 明确排除
- 团队协作、共享 Project、多人编辑和审批流。
- AI 自动生成完整 Workflow。
- 一个 Project 同时维护多张 Workflow 图。
- Workflow 状态、节点类型与执行器的完全自定义。
- 课程表截图识别；V1 仅接受文件导入。
- 移动端完整画布建模；移动端保留基础编辑能力。
- 专注计时器、番茄钟和沉浸式专注模式。
- 自动排程中的同 Project 聚类或上下文切换优化。
- 硬冲突与软冲突分级；V1 仅保留统一冲突提示与锁定属性。
- 通过飞书发送日报、晚报和周报；统计报告统一在网页内呈现。
> **范围原则：** V1 优先完成“计划—排程—提醒—执行—回顾”的闭环。高级协作、开放式自动化和复杂自定义进入后续版本。

| 入口 | 定位 | 主要内容 |

| Projects | 层级化内容与流程管理 | 文件夹树、Project 主页、Workflow、资料、日程与 Todo |

## 5.2 Project 内部结构
```text
Project / 文件夹
├── Overview（描述、Deadline、进度、近期活动）
├── Todo
├── Calendar
├── Workflow（V1 每个 Project 最多一张）
├── Files & Links
└── Child Projects（可无限嵌套）
```
> **统一模型：** Project 没有额外参数时呈现为普通文件夹；添加描述、Deadline、Todo、Workflow 或资料后，自然升级为项目主页。

# 6. 核心领域模型

## 6.1 实体关系
| 实体 | 关键字段 | 主要关系 |
| --- | --- | --- |
| User | 账号、时区、偏好、通知配置 | 拥有全部私有业务数据；每位用户独立配置飞书与外部日历 |
| Project | 名称、父级、描述、Deadline、颜色、归档状态 | 可嵌套；拥有 Todo、日程、附件和至多一张 Workflow |
| Todo | 状态、优先级、难度、时间、工时、重复、提醒 | 属于一个主 Project；可有子任务、多时间块和附件 |
| CalendarEntry | 起止时间、类型、锁定、完成状态、来源 | 可独立存在，也可关联 Todo、Workflow 节点或课程 |
| TimeBlock | 起止时间、完成状态、关联对象 | 是 CalendarEntry 的任务排程形态；一个 Todo/节点可对应多个 |
| WorkflowGraph | 画布、版本、布局 | V1 与 Project 一对一 |
| WorkflowNode | 类型、状态、位置、任务字段 | 可作为 Todo 节点、控制节点、里程碑、说明或跨流程跳转 |
| WorkflowEdge | 源节点、目标节点、标签、条件、延迟 | 表达普通依赖、条件分支与回环 |
| Reminder | 触发时间、通道、强提醒参数、状态 | 可关联 Todo、日程或节点 |
| Notification | 类型、已读状态、关联对象 | 承载提醒结果、节点解锁、同步冲突与系统消息 |
| ExternalBinding | Apple 事件 ID、同步状态、版本 | 维护网站对象与外部日历对象映射 |
| Attachment | 文件、URL、Markdown | 可关联 Project、Todo、节点和日程 |
| AuditLog | 操作者、动作、前后差异、来源 | 记录 AI、同步、提醒和用户写操作 |

## 6.2 关键关系规则
- 一个 Todo 或日程只能拥有一个主 Project；标签可跨 Project 多选。
- 文件夹层级采用 Project 自关联实现，允许无限嵌套；界面提供折叠与面包屑。
- 任务型 Workflow 节点具备 Todo 字段，并同步出现在 Todo 列表中。控制节点不进入 Todo 列表。
- 一个 Todo 或任务节点可关联多个时间块；每个时间块独立记录完成情况和实际时长。
- Project 进度按已完成 Todo 数除以有效 Todo 总数计算；取消项与回收站项不计入分母。
- 所有外部同步对象保留来源和外部 ID；本地标签、Project、Workflow 关系不覆盖到外部日历。

| CAL-001 | 完整视图 | 提供月、周、日、时间轴和列表视图，用户可设置默认视图。 |
| CAL-002 | 允许重叠 | 日程可任意重叠；系统显示冲突提示和同时进行数量，不阻止保存。 |

# 8. 核心状态机与业务规则

## 8.1 Todo 状态机
```text
未开始 → 进行中 → 已完成
   └────→ 等待 ────┘
任意未完成状态 → 已取消
Deadline 已过且未完成 → 计算属性“逾期”
```
| 规则 | 说明 |
| --- | --- |
| 完成时间 | 进入已完成时写入实际完成时间；撤销完成时保留审计记录。 |
| 等待 | 等待状态可设置等待原因或恢复时间。 |
| 逾期 | 逾期不替代业务状态；“进行中且逾期”可以同时存在。 |
| 重复 Todo | 每个周期创建新实例，上一周期状态不影响下一周期。 |

## 8.2 CalendarEntry 状态机
```text
已计划 → 进行中 → 已完成
   └──────────→ 已取消
任务关联日程到期且未完成 → 未完成
普通事件到期且未操作 → 已结束（可补记完成）
```
产品决策：所有日程都提供“完成”动作；只有任务关联日程会在到期后进入“未完成”，避免会议等普通事件制造无意义逾期。

## 8.3 Workflow 节点状态机
```text
锁定 ──前置满足──→ 可开始 → 进行中 → 已完成
                         └→ 等待 ─────┘
可开始 / 进行中 / 等待 → 已跳过
已完成或已跳过 → 参与下游解锁判断
```
| 场景 | 解锁结果 |
| --- | --- |
| 单前置 | 前置完成或跳过后，下游进入可开始。 |
| AND 汇合 | 全部有效前置满足后进入可开始。 |
| OR 汇合 | 任一有效前置满足后进入可开始。 |
| 条件节点 | 用户手动选择出口后，仅激活选中分支。 |
| 延迟连线 | 前置满足后进入等待，到达目标时间再进入可开始。 |
| 回环 | 用户手动选择回环分支；系统记录迭代次数但不自动循环。 |

## 8.4 时间块与 Todo 联动
| 关联数量 | 完成时间块后的行为 | Todo 完成方式 |
| --- | --- | --- |
| 1 个 | 时间块标记完成并累计实际耗时。 | 自动完成 Todo。 |
| 2 个及以上 | 当前时间块完成，进度显示已完成块数与累计时长。 | 用户单独完成 Todo。 |
| 0 个 | 无时间块进度。 | 用户直接完成 Todo。 |

## 8.5 强提醒状态机
```text
待触发 → 已发送 → 等待确认
                     ├─ 到达间隔且未“已知晓” → 再次发送
                     ├─ 达到最大次数 → 停止升级并保留未确认状态
                     └─ 用户“已知晓” → 已确认，终止当前提醒链
```
完成 Todo、稍后提醒或延后日程不会直接终止强提醒链；动作流程需要包含明确的“已知晓”才能结束。

## 8.6 AI 写操作规则
- 模型输出必须通过 JSON Schema 校验。
- 后端重新检查用户权限、对象版本、时间格式、重复规则和冲突。
- 所有写操作进入预览页，用户确认后执行。
- 对象存在多个匹配时，先显示候选，不自动猜测。
- 批量修改必须展示影响数量和逐项差异。
- 执行采用幂等键，避免重复点击造成重复创建。

## 8.7 Apple 同步冲突规则
| 情况 | 处理 |
| --- | --- |
| 仅网站发生变化 | 同步到 Apple。 |
| 仅 Apple 发生变化 | 同步到网站；导入事件保持来源标记和默认锁定。 |
| 双方均发生变化 | 进入冲突状态，通知用户选择版本。 |
| Apple 删除事件 | 网站对象进入回收站。 |
| 网站删除事件 | 进入回收站后向 Apple 发起删除或解除映射，行为需在删除确认中展示。 |

# 13. 验收标准
| 编号 | 验收项 | 通过条件 |
| --- | --- | --- |
| AC-001 | 账号隔离 | A 用户无法通过接口、搜索、附件链接或通知访问 B 用户数据。 |
| AC-002 | Project 嵌套 | 用户可创建多层 Project，并通过拖拽改变父级；面包屑与树同步更新。 |
| AC-003 | 重叠日程 | 同一时间可保存至少三个日程，并能在三种样式之间切换。 |
| AC-004 | 拖入日历 | 从 Todo 或 Workflow 任务节点拖入日历后生成关联时间块。 |
| AC-005 | 多时间块 | 完成其中一个时间块只累计进度；单时间块 Todo 自动完成。 |
| AC-006 | Workflow AND | 两个前置中任一未完成时下游保持锁定；全部满足后进入可开始。 |
| AC-007 | Workflow OR | 任一前置满足后下游进入可开始。 |
| AC-008 | 跳过 | 节点标记已跳过后继续参与下游解锁。 |
| AC-009 | 循环 | 用户可以绘制回环并手动推进，不产生自动无限执行。 |
| AC-010 | 自动布局 | 整理布局后节点与边的逻辑、标签和状态保持不变。 |
| AC-011 | AI 预览 | 任何 AI 写操作在确认前不改变数据库。 |
| AC-012 | AI 歧义 | 时间歧义或对象歧义时展示三个候选或对象选择。 |
| AC-013 | 批量排程 | 候选方案遵守锁定日程、依赖、拆分设置和 Deadline。 |
| AC-014 | 飞书提醒 | 网页关闭后仍可触发飞书卡片，并能通过安全动作链接打开或执行操作。 |
| AC-015 | 强提醒 | 未点已知晓时按设定间隔重复，达到上限停止升级并保留未确认。 |
| AC-016 | PWA 兜底 | 飞书失败时生成失败记录，并在已授权设备尝试 PWA/浏览器通知。 |
| AC-017 | 重复日程 | 修改重复实例时只出现“仅本次”“本次及以后”。 |
| AC-018 | Apple 冲突 | 双方修改时不静默覆盖，用户可选择保留版本。 |
| AC-019 | Apple 删除 | Apple 侧删除后网站对象进入回收站。 |
| AC-020 | 课程导入 | 导入前可预览课程、周次、时间和冲突，确认后进入课程 Project。 |
| AC-021 | 回收站 | 删除对象 30 天内可恢复，超过保留期可被彻底删除。 |
| AC-022 | 备份恢复 | 用户能查看备份状态并从指定日期恢复，恢复前生成保护快照。 |
| AC-023 | Today 定制 | 用户可调整模块开关和顺序，刷新及跨设备后保持。 |
| AC-024 | 移动端 Workflow | 手机可查看流程、修改节点状态和字段；复杂编辑提供桌面端提示。 |

# 14. 风险与实施前置
| 风险 / 依赖 | 影响 | 应对 |
| --- | --- | --- |
| Apple 双向同步接入方式待技术验证 | 影响连接流程、重复规则与冲突检测。 | 先做字段映射和同步状态模型，再进行独立技术验证；接口层保持可替换。 |
| 极简课程表导出格式未知 | 无法提前确认一键导入覆盖率。 | 获取真实样本，建立适配器与导入预览；无法识别字段时允许用户映射。 |
| 飞书 Webhook 动作回写 | 卡片动作可能需要通过网页安全链接完成。 | 统一使用限时签名 action URL；后续可升级飞书应用回调。 |
| Workflow 回环与复杂图 | 错误配置可能导致流程难以理解。 | 提供回环提示、迭代计数、自动布局、分组和状态诊断。 |
| 无固定可用时段 | AI 可能提出深夜等不合适候选。 | 默认提供多个方案；支持快速排除时间，并在当前会话重算。 |
| PWA 通知能力差异 | 部分设备可能无法使用完整通知能力。 | 设置页检测权限与能力，保留飞书和站内通知。 |
| 强提醒过度打扰 | 高频提醒造成反感。 | 要求用户显式开启，并设置最大次数；提供当前链已知晓。 |
| 多源修改 | AI、Apple、用户和提醒动作可能并发写入。 | 使用对象版本、幂等键、冲突提示和审计差异。 |
